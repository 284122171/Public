## 一、产品定位

**"AI 是信徒手中的利器，不是祭坛上的偶像。"**

AI 在本应用中的角色是 **圣经学习辅助工具**，而非属灵权威。它的目标是：
- 帮助信徒更好地 **理解** 圣经
- 降低 **查经门槛**，让初信者也能自主学习
- 提供 **个性化** 的灵修陪伴体验
- **绝不** 替代牧师、教会和真实的团契关系

## 二、功能模块规划

### 2.1 第一优先级（MVP 核心功能）

| 功能 | 描述 | 用户场景 | 对应页面 |
|------|------|----------|---------|
| **经文解释** | 选中经文 → AI 解读上下文、历史背景、原文含义 | "这节经文什么意思？" | BibleReaderPage → 选中经文 → 底部操作栏"问AI" |
| **智能问答** | 基于圣经知识的对话式问答 | "圣经怎么看待饶恕？" | AiChatPage |
| **每日灵修** | 根据今日经文自动生成个人化灵修引导 | 早晨灵修5分钟 | HomePage → 每日灵修卡片 |
| **经文搜索** | 自然语言找经文，不需要记住章节号 | "关于爱的经文有哪些？" | SearchPage |

### 2.2 第二优先级（增值功能）

| 功能 | 描述 |
|------|------|
| **AI 读经计划生成** | 输入主题/天数 → AI 生成定制读经计划 |
| **经文对比** | 多译本对比 + AI 解释翻译差异原因 |
| **祷告辅助** | 基于经文和用户处境生成祷告提示词 |
| **儿童模式** | 用简单语言给孩子讲圣经故事 |
| **原文工具** | 希伯来文/希腊文词义查询与解析 |
| **读经笔记AI摘要** | 对用户的读经笔记进行归纳总结 |

### 2.3 功能交互流程

```
【经文解释】
  用户阅读经文 → 长按选中 → 点击"问AI" → 
  后端检索相关上下文经文(RAG) → 
  AI 生成解释（含历史背景+原文释义+应用建议）→ 
  展示在底部弹窗/新页面

【智能问答】
  用户打开AI对话 → 输入问题 → 
  后端NLP意图识别 → 向量检索相关经文 → 
  注入Prompt → AI流式回复 → 
  回复中经文引用可点击跳转

【每日灵修】
  系统获取今日经文(VOTD) → 
  结合用户读经历史 → AI生成灵修引导 → 
  包含：经文、背景、默想问题、祷告词 → 
  缓存24小时（同一用户同一天不重复生成）
```

### 4.2 关键设计原则

**1. App 不直接调用 AI API，统一走后端代理**
- API Key 安全（不暴露在客户端）
- 可做 Prompt 过滤和内容审核
- 统一计费、限额、缓存
- 可随时切换底层模型，App 无感知

**2. 流式输出 (SSE)**
- AI 回复采用 Server-Sent Events 流式推送
- 用户体验：逐字显示，无需等待完整回复
- 降低首字延迟感知

**3. 缓存策略**
- 经文解释结果缓存（同一经文同一语言，24小时内复用）
- 每日灵修缓存（每天每用户只生成一次）
- 热门问题缓存（如"约翰福音3:16什么意思"）

### 4.3 RAG（检索增强生成）方案

```
用户提问
    │
    ▼
┌─────────────────┐
│ 1. 意图识别      │  判断是经文查询、神学问题、灵修请求等
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 2. 向量检索      │  在圣经向量库中找到 Top-K 相关经文
│    (Embedding)   │  使用经文的章节+内容作为检索单元
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 3. 上下文组装    │  将检索到的经文 + System Prompt + 用户问题
│    (Prompt)      │  组装成完整的 Prompt
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 4. AI 生成      │  调用 DeepSeek 生成回答
│    (LLM)        │  要求必须引用检索到的经文
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 5. 后处理       │  验证经文引用准确性
│    (Verify)     │  内容安全过滤
└─────────────────┘
```

**向量数据库选择**：
- 推荐 **ChromaDB**（轻量、Python原生、适合初期）
- 未来可迁移到 **Milvus** 或 **Pinecone**

**Embedding 模型**：
- DeepSeek Embedding 或 `text-embedding-3-small` (OpenAI)
- 圣经全文约 80万字（中文和合本），向量化后存储量很小

## 五、内容规范（红线制度）

### 5.1 System Prompt 模板

```text
你是"圣经助手"，一个专注于帮助用户学习和理解圣经的AI工具。

【身份定位】
- 你是圣经学习辅助工具，不是牧师、神父、先知或任何属灵权威
- 你的知识来源于圣经经文和学术研究，不代表任何宗派立场
- 始终保持谦卑、温和、尊重的语气

【回答原则】
- 所有经文引用必须标注准确的 书卷名 章:节（如：约翰福音 3:16）
- 禁止编造不存在的经文，只能引用系统提供的检索结果中的经文
- 回答应包含：经文原文 → 历史背景 → 含义解读 → 生活应用
- 遇到有争议的教义问题，客观呈现主要观点（改革宗、天主教、东正教等），不做裁判
- 适当建议"可以与你的牧者或教会进一步探讨"

【多语言规则】
- 根据用户的提问语言回复（中文提问用中文答，英文提问用英文答）
- 引用经文时，中文使用和合本（CUV），英文使用 NIV 或 ESV
- 经文引用格式：「经文内容」—— 书卷名 章:节

【禁止行为 — 严格执行】
- ❌ 不可自称是神、耶稣、圣灵、先知或任何属灵权威
- ❌ 不可预言未来、解梦、算命、占卜
- ❌ 不可攻击、贬低任何宗派、教会或宗教
- ❌ 不可对"哪个宗派是正确的"给出结论性判断
- ❌ 不可讨论政治敏感话题
- ❌ 不可鼓励用户脱离教会、不聚会
- ❌ 不可提供医疗、法律、投资建议

【危机处理】
当检测到用户表达自杀、自残、严重抑郁等危机信号时：
1. 立即表达关心和同理心
2. 引用安慰性经文（如诗篇 23、以赛亚书 41:10）
3. 强烈建议联系专业帮助：
   - 中国：全国24小时心理援助热线 400-161-9995
   - 美国：988 Suicide & Crisis Lifeline
   - 国际：befrienders.org
4. 建议联系牧师或信任的教会弟兄姐妹
```

|------|---------|---------|-----------|--------|--------|
| 初期 | 100 | 5次 | 75万 | ¥1.5 | ¥45 |
| 增长 | 1,000 | 5次 | 750万 | ¥15 | ¥450 |
| 成熟 | 10,000 | 5次 | 7500万 | ¥150 | ¥4,500 |
| 大规模 | 100,000 | 5次 | 7.5亿 | ¥1,500 | ¥45,000 |

> 即使10万日活，月成本仅 ¥4.5万，远低于 GPT-4o 的 ¥315万/月

### 6.3 成本优化手段

1. **缓存热门问题**：相同经文解释缓存24h，命中率预计 30%+
2. **分级模型调用**：简单问题用 V3 低配，复杂问题才用 R1
3. **Prompt 精简**：精心设计 System Prompt，减少冗余上下文
4. **限制对话轮数**：单次对话最多10轮，超出建议开启新对话
5. **异步批处理**：每日灵修可在凌晨批量生成，降低峰值压力

## 八、模型降级与容错策略

### 8.1 语言感知降级链

降级不是固定链路，而是**根据用户语言选择不同降级路径**：

```
【中文/英文/日韩用户】
DeepSeek V3 → 通义千问 Qwen → Claude (via OpenRouter) → 预置回复

【欧洲语言/小语种用户】
Claude 3.5 → DeepSeek V3 → 通义千问 Qwen → 预置回复
```

## 十、安全与合规

### 10.1 数据安全
- 用户对话内容加密存储，仅用户本人可查看
- 不将用户对话数据用于模型训练
- 提供"删除所有对话记录"功能

### 10.2 内容合规
- 所有 AI 输出经过内容过滤层
- 保留 AI 回复日志（30天），用于质量审计
- 用户可举报不当 AI 回复

### 10.3 隐私声明
- 明确告知用户：对话内容会发送到第三方 AI 服务
- 不收集与圣经学习无关的个人信息
- 遵守 GDPR（欧洲用户）和个人信息保护法（中国用户）
